How this simulator works

      
Write an Arduino Cloud sketch, press Upload & run, and the sketch drives a virtual ESP32-WROOM-32 DevKit. Variables you register with ArduinoCloud.addProperty() show up on the dashboard. A switch or slider there reaches the board on the next ArduinoCloud.update() and calls your onXxxChange() function, the same flow as the real Arduino IoT Cloud.

      
What is simulated

      
    
        
  • GPIO, INPUT_PULLUP, interrupts, 12-bit ADC (0–4095), PWM (analogWrite, ledcWrite), tone(), DAC
    • 
        
  • ESP32 quirks: input-only GPIO 34–39, ADC2 pins stop working while WiFi is on, flash pins 6–11, no A1/A2 or D4-style pin names
    • 
        
  • Wi-Fi join and retry, Arduino Cloud connection, property sync (on change, periodic, min delta), cloud-wins sync on connect
    • 
        
  • Libraries: DHT (DHT11 / DHT22), ESP32Servo, Wire (I2C scan), LiquidCrystal_I2C, WiFi, ArduinoIoTCloud, Serial (print, printf, read)
    • 
        
  • Parts: LED, button, potentiometer, LDR, DHT11/22, PIR, IR obstacle sensor, HC-SR04 ultrasonic (pulseIn), rain and soil sensors, relay, buzzer, servo, DC motor with L298N, 16×2 I2C LCD
    • 
        
  • Cloud Triggers: alert by email or push notification when a bool or String variable changes. The alerts are simulated and shown on screen.
    • 
      

      
Limits

      
    
        
  • The sketch is translated to JavaScript in your browser, not compiled for the Xtensa CPU. Timing is approximate and it is not cycle-accurate.
    • 
        
  • Plain sketch C++ only: no class/struct, templates, or pointers beyond strings and arrays. Integer overflow is not modelled.
    • 
        
  • Nothing leaves your browser. There is no real Wi-Fi or MQTT traffic.
    • 
      

      
Moving to a real board

      
Create a Thing in Arduino Cloud with the same variable names, types and permissions, then paste the sketch. The examples use the same file layout that Arduino Cloud generates.
